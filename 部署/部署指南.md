# 部署指南 · 纯净 Ubuntu 手动部署

> 适用：全新的 Ubuntu 20.04 / 22.04 / 24.04（x86_64）服务器，手动把它变成一个能访问的静态站点。
> 全程大约 **5 分钟**。服务器上**不需要安装 Node / pnpm** —— 站点在本地构建好，服务器只负责用 nginx 把文件发出去。

## 0. 开始前：先定好 3 个变量

后面所有命令都会用到这三个值，**先想好，一路套用**：

| 变量 | 本次建议值 | 说明 |
|---|---|---|
| `服务器IP` | 例如 `1.2.3.4` | 你的 Ubuntu 服务器公网 IP |
| `端口` | **25565** | 站点对外端口；想用 80 就填 `80` |
| `站点目录` | `/var/www/yuki-voice-button` | 放 dist 文件的位置，按需改 |

> ⚠️ **本指南用 root 登录演示**。若用普通用户，请给需要 root 权限的命令加 `sudo`。

## 1. 本地：构建 + 打包

在项目目录（`D:\Webs\Yuki-Voice-Button`）执行：

```bash
pnpm build
```

成功后会生成 `dist/` 目录。**先确认它里面有这些**：

```
dist/
├─ index.html          ← 首页「渺の怪动静」
├─ request/index.html  ← 歌单页「渺の歌单」
├─ about/index.html    ← 关于页
├─ _astro/             ← CSS / JS
├─ audio/              ← 音频（★ 先把 mp3 放进去再 build！）
├─ fonts/ icons/ thumbs/
├─ favicon.ico
└─ robots.txt
```

> ★ **音频必须在构建前放进 `public/audio/`**（`<分组名>/` 与 `songs/`），否则部署上去按钮点了会提示"文件不存在"。

打包成一个文件，方便上传：

```bash
tar -czf site.tar.gz -C dist .
```

（Windows 10+ 自带 `tar`，直接在上面这条命令所在的 PowerShell 里跑即可。）

## 2. 服务器：登录并检查环境

```bash
ssh root@服务器IP
```

登录后先确认三件事（可选但推荐）：

```bash
cat /etc/os-release | head -3      # 确认是 Ubuntu
df -h /                            # 确认磁盘有空间
ss -lntp                           # 看端口占用（确认你选的端口是空的）
```

## 3. 上传站点文件

### 方式 A：命令行（推荐）

**在本地**（不是服务器上）执行：

```bash
# 上传压缩包
scp site.tar.gz root@服务器IP:~/

# 服务器上解压到站点目录
ssh root@服务器IP 'mkdir -p /var/www/yuki-voice-button && tar -xzf ~/site.tar.gz -C /var/www/yuki-voice-button && rm -f ~/site.tar.gz && echo OK'
```

确认解压结果：

```bash
ssh root@服务器IP 'ls /var/www/yuki-voice-button'
# 应该看到 index.html  request  about  _astro  audio  fonts  icons  thumbs  favicon.ico  robots.txt
```

### 方式 B：图形工具（FinalShell / WinSCP / Xftp）

1. 连接服务器（SFTP，端口 22）；
2. 进到 `/var/www/`，新建目录 `yuki-voice-button`；
3. 把**本地 `dist/` 里面的所有内容**（不是 dist 文件夹本身）拖进去。

> 两种方式等价，选顺手的即可。

## 4. 安装 nginx

```bash
apt update
apt install -y nginx
```

确认状态（应为 `active` + `enabled`，即开机自启）：

```bash
systemctl is-active nginx
systemctl is-enabled nginx
nginx -v                       # 会显示版本，如 nginx/1.18.0 (Ubuntu)
```

---

## 5. 写入站点配置

直接**整段复制**到服务器终端执行（把 `25565` 改成你的端口）：

```bash
tee /etc/nginx/sites-available/yuki > /dev/null <<'EOF'
server {
    # ★ 站点端口（改这里）
    listen 25565;
    listen [::]:25565;

    # 没有域名就保持 _ ；有域名就填域名
    server_name _;

    # ★ 站点目录（改这里，要和第 3 步解压的位置一致）
    root /var/www/yuki-voice-button;
    index index.html;

    charset utf-8;

    location / {
        try_files $uri $uri/ =404;
    }

    # HTML 不缓存：改完刷新就能看到新内容
    location ~* \.html$ {
        add_header Cache-Control "no-cache";
        try_files $uri =404;
    }

    # 带哈希的构建产物长缓存
    location /_astro/ {
        expires 1y;
        add_header Cache-Control "public, immutable";
        try_files $uri =404;
    }

    # 图标字体：Ubuntu 自带的 nginx 没映射 .ttf，不补会返回 application/octet-stream
    location ~* \.(ttf|otf|woff|woff2|eot)$ {
        types {
            font/ttf   ttf;
            font/otf   otf;
            font/woff  woff;
            font/woff2 woff2;
        }
        expires 30d;
        add_header Cache-Control "public";
        try_files $uri =404;
    }

    # 图标 / 缩略图
    location ~* ^/(icons|thumbs|fonts)/ {
        expires 30d;
        add_header Cache-Control "public";
        try_files $uri =404;
    }

    # 压缩
    gzip on;
    gzip_vary on;
    gzip_min_length 1024;
    gzip_types text/css text/plain application/javascript application/json image/svg+xml;

    # 不暴露隐藏文件
    location ~ /\. { deny all; }

    access_log /var/log/nginx/yuki.access.log;
    error_log  /var/log/nginx/yuki.error.log;
}
EOF
```

> 这份配置与仓库里的 `部署/nginx.conf` **完全一致**，也可以直接上传那个文件替代上面这段。

启用站点并加载：

```bash
ln -sf /etc/nginx/sites-available/yuki /etc/nginx/sites-enabled/yuki
nginx -t                       # 必须显示 syntax is ok / test is successful
systemctl reload nginx
```

> **CentOS / RHEL / Rocky 用户**：把上面的 `sites-available/yuki` 换成 `/etc/nginx/conf.d/yuki.conf`，不用建软链。

## 6. 放行端口

### 6.1 服务器本机防火墙

Ubuntu 默认 `ufw` 是**关闭**的（`ufw status` 显示 inactive 就不用管）。若已启用：

```bash
ufw status                              # 看是否 active
ufw allow 25565/tcp                     # 放行你的端口
ufw reload
```

### 6.2 ★ 云服务商安全组（最容易漏的一步）

阿里云 / 腾讯云 / 华为云等，**必须在控制台的「安全组 / 防火墙」里添加入方向规则**：

| 项 | 值 |
|---|---|
| 协议 | TCP |
| 端口 | 你的端口（如 `25565`） |
| 来源 | `0.0.0.0/0`（对所有人开放）或你群友所在的内网网段 |
| 动作 | 允许 |

漏了这步的典型症状：**服务器本机 `curl` 正常，但从外面打不开**。

## 7. 验证

### 7.1 服务器上（自测）

```bash
ss -lntp | grep 25565                                  # 应看到 nginx 在监听
curl -sI http://127.0.0.1:25565/ | head -3             # 应返回 HTTP/1.1 200 OK
curl -s http://127.0.0.1:25565/ | grep -o '<title>[^<]*</title>'   # 看标题对不对
```

### 7.2 从你自己的电脑（公网）

浏览器打开：**`http://服务器IP:25565/`**

### 7.3 对照检查清单

| # | 检查项 | 期望 |
|---|---|---|
| 1 | 首页 `/` | 显示「渺の怪动静」+ 搜索框 + 5 个分组 |
| 2 | 歌单页 `/request/` | 显示「渺の歌单」+ 右上角「歌曲类型 / 原唱作者」开关 |
| 3 | 关于页 `/about/` | 显示贡献者与素材来源 |
| 4 | 图标字体 | 顶栏/搜索框/播放控件里的图标**都是正常符号**，不是方块或空白 |
| 5 | 点击音效 | 底部 72% 处出现悬浮播放控件，且滚动时**停在屏幕上不动** |
| 6 | 分享按钮 | 点后**屏幕顶部中间**弹出「已复制分享链接」 |
| 7 | 主题切换 | 日间/夜间/随系统三种模式颜色正常 |
| 8 | 侧边栏 | 点左上角汉堡能打开，友链/关注老大都在 |
| 9 | F12 控制台 | 没有红色报错（字体 404、CSS 404 都会在这里报） |
| 10 | 音频 | 有 mp3 的话能播放、能拖进度条；没有则提示"文件不存在"（正常） |

### 7.4 命令行抽查资源 MIME

```bash
curl -sI http://服务器IP:25565/fonts/SegoeFluentIcons.ttf | grep -i content-type   # 应为 font/ttf
curl -sI http://服务器IP:25565/_astro/xxxxx.css | grep -i content-type              # 应为 text/css
```

## 8. 以后怎么更新内容

改完 `src/data/` 里的内容后，**重复这三步**即可：

```bash
# 1) 本地重新构建 + 打包
pnpm build
tar -czf site.tar.gz -C dist .

# 2) 上传
scp site.tar.gz root@服务器IP:~/

# 3) 服务器：覆盖站点目录
ssh root@服务器IP 'rm -rf /var/www/yuki-voice-button/* && tar -xzf ~/site.tar.gz -C /var/www/yuki-voice-button && rm -f ~/site.tar.gz && echo DONE'
```

> **只换静态文件不需要重启 nginx**。只有改了 `/etc/nginx/` 里的配置才需要 `nginx -t && systemctl reload nginx`。
>
> 只新增了几首音频时，也可以只传音频目录：
> `scp -r dist/audio/* root@服务器IP:/var/www/yuki-voice-button/audio/`

## 9. 排查手册

| 症状 | 最可能的原因 | 怎么查 / 怎么修 |
|---|---|---|
| 服务器本机能 curl，外面打不开 | **云安全组没放行** | 控制台加 TCP 入方向规则（见 6.2）；用 `ss -lntp` 确认 nginx 在监听 |
| 完全连不上（超时） | 端口没监听 / 防火墙拦了 | `systemctl status nginx`；`ufw status`；`ss -lntp \| grep 端口` |
| **403 Forbidden** | 站点目录权限或没有 index.html | `ls -l /var/www/yuki-voice-button` 确认有 `index.html`；`chmod -R 755 /var/www/yuki-voice-button` |
| **404 Not Found** | `root` 路径写错，或解压层级多了一层 | 确认 `/var/www/yuki-voice-button/index.html` 直接存在（不是多套了一层目录） |
| 首页能开，但**样式全丢、按钮不响应** | CSS/JS 404 | F12 → Network 看 `_astro/*.css` 是否 404；多半是**部署在子目录**却没配 `base` |
| 子目录（如 `http://IP/yuki/`）访问异常 | 没配 Astro `base` | 在 `astro.config.mjs` 加 `base: '/yuki'` 重新 build；nginx 里把 `root` 换成 `alias` |
| 图标显示成方块/空白 | 字体没加载 | 看 `/fonts/SegoeFluentIcons.ttf` 是否 200、MIME 是否 `font/ttf`（配置里已修） |
| 点了音效提示"文件不存在" | mp3 没上传 / 路径不对 | 确认 `audio/` 下有对应文件，且 `voices.ts` 里的 `path` 与文件名**大小写完全一致** |
| 改了内容但页面没变 | 浏览器缓存 | 硬刷新 `Ctrl + F5`；确认上传的是新构建的 `dist` |
| **504 / 502** | 静态站点不会出现 | 若出现说明访问到了别的服务，检查是否端口冲突 |

看日志：

```bash
tail -n 50 /var/log/nginx/yuki.error.log
tail -n 50 /var/log/nginx/yuki.access.log
```

## 10. 可选加强

### 10.1 顺便让 80 端口也指向同一个站点

装完 nginx 后，`/etc/nginx/sites-enabled/default` 会占用 80 端口显示欢迎页。不想要的话：

```bash
rm /etc/nginx/sites-enabled/default
systemctl reload nginx
```

或者把配置里 `listen 25565;` 改成 `listen 80;`（并加一条 `listen 25565;` 也可同时监听两个端口）。

### 10.2 上 HTTPS（有域名后）

```bash
apt install -y certbot python3-certbot-nginx
certbot --nginx -d your.domain.com
```

### 10.3 安全建议

- 把 SSH 改成**密钥登录**并关闭密码登录；
- 不要长期用 root 直接登录；
- 只放行必要的端口。
