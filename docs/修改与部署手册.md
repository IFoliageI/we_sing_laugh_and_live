### 0.2 先记住三件事

1. **内容只改 `data/content.db`。** 不要手改 `src/data/voices.ts`、`songs.ts`；`src/data/content.json` 和 `data/content-dump.sql` 是自动生成物，也不手改。`data/content.db` 已入库，改完要随代码一起提交；`data/backups/` 不入库。
2. **改完数据库要同步。** `pnpm build` / `pnpm dev` 启动时会自动跑一次 `content:sync`；但 `dev` 运行期间再改库不会自动同步，需要手动 `pnpm content:sync` 或重启。
3. **上线只上传 `dist/`。** 服务器上不需要 Node、不需要 SQLite；`dist/` 里也不要手改，每次构建都会覆盖。

**改链接的格式**（`sideLinks` 和 `friendLinks` 完全一样）：

```ts
export const sideLinks: Links[] = [
  { title: '老大的主页', url: 'https://space.bilibili.com/3707066919160157', icon: '/icons/external-link.ico' },
  // 加一行 = 多一个链接；删一行 = 少一个链接
];
```

- `title`：抽屉里显示的文字。
- `url`：点击后跳转的完整网址。
- `icon`：`/icons/` 下的图片（或完整图床 URL）。想给某个链接换专属图标，把图标放进 `public/icons/`，改这一项即可。

> ⚠️ 当前实际状态：`friendLinks` 不是空的，而是有一条 `友站 → https://example.com`。直接上线会让访客点到一个示例域名；发布前请替换成真实友链，或改成 `export const friendLinks: Links[] = [];`。
>
> ⚠️ `site.title` 只改首页标签标题。歌单页和关于页的标签标题在各自 `.astro` 文件的 `<BaseLayout title="...">` 里写死（见 1.2），要一起改。

**想加一个抽屉导航项？** 必须同时真的新建对应页面，否则会 404。例如新增 `/links/` 页面后，在 `<nav>` 里复制一段：

```astro
<a class="drawer__item" href={assetUrl('/links/')}>
  <span class="emoji sficon">&#xE80F;</span><span>链接</span>
</a>
```

- 站内路径一律用 `assetUrl(...)` 包一层，子路径部署（1.6）时才不会 404。
- 外部链接写成 `href="https://..." target="_blank" rel="noopener"`，并且不用 `assetUrl`。
- 链接数据优先放 `site.ts`（`sideLinks` / `friendLinks`）；只有三个固定页面才直接写在 `BaseLayout.astro` 的 `<nav>` 里。
- `friendLinks` 为空会自动隐藏整栏；`sideLinks` 为空时「关注老大谢谢咕」标题仍会显示（只是下面没链接），不想留空标题就至少保留一条，或删掉 `BaseLayout.astro` 里对应的小标题和 `<nav>`。

**验证**：`pnpm dev` → 打开抽屉，逐项点击；三个页面都看一遍；`pnpm build` 后检查 `dist/` 里的导航链接是否带部署前缀（子路径部署时）。

## 1.4 配色与主题（`src/styles/global.css`）

所有颜色集中在文件顶部的两个块：

- `:root { ... }`：浅色主题（默认）。
- `html.dark { ... }`：深色主题，只覆盖需要变的变量。

先改 `:root`，再改 `html.dark` 里同名变量；两套都改完才算完成。

**最常改的 4 个变量**：

| 变量 | 浅色当前值 | 深色当前值 | 控制什么 | 改的时候注意 |
|---|---|---|---|---|
| `--accent-500` | `#E9DACD` | `#917D73` | ★ 主色：选中态、FAB 齿轮、部分按钮/边框的基色 | 改完必须同时检查 `--on-accent`；深色主题的主色和浅色主题不是同一个值 |
| `--on-accent` | `#3A2C1F` | `#221A15` | 放在「主色底」上的文字/图标颜色 | 主色是浅色 → 配深字；主色是深色 → 配浅字。否则齿轮、开关的选中项会看不清 |
| `--bg` | `#F7F3EF` | `#15110E` | 整页背景 | 同时看 `--surface` / `--surface-2`，三个一起调才协调 |
| `--play-500` | `#8B6A50` | `#75583F` | 播放中按钮的渐变起点（`--play-400/600` 配套） | 播放态按钮上是**白字**，这三个值要够深；不要换成浅色 |

其它常用变量：`--text`（正文）、`--text-2`（次级文字）、`--text-3`（页脚/提示）、`--border`（描边）、`--radius-lg/md/sm`（圆角）、`--shadow-*`（阴影）。

示例：只换主色（浅色改成淡青，深色改成中青）：

```css
:root {
  --accent-500: #CFE3E0;
  --on-accent: #1F3A37;
}

html.dark {
  --accent-500: #5F8A85;
  --on-accent: #10211F;
}
```

> 「屏幕上某一块具体该改哪个变量」看 [配色修改指南](../配色修改指南.md) 的逐块对照表；这里只列最容易改的入口。

**换色时容易漏的 4 个地方**（不在 `global.css` 里）：

1. `src/data/site.ts` 的 `themeColor`（当前 `#E9DACD`）。
2. `public/icons/external-link.ico`（当前 `sideLinks` 实际引用的侧栏外链图标；另有 `external-link.svg` 备用）。
3. `public/thumbs/placeholder.svg`（缩略图占位）。
4. `public/favicon.svg`（备用图标，当前站点 favicon 实际用 `favicon.ico`）。

**验证**：`pnpm dev` → 顶部主题菜单切「日间 / 夜间 / 随系统」三遍；重点看：

- 播放中的按钮（深色底白字）是否清楚；
- 右下角齿轮 FAB 的图标（`--on-accent`）是否清楚；
- 歌单「展示方式」选中项；
- 页脚/副标题等弱文字是否还看得清。

改完 `pnpm build`，部署后硬刷新 `Ctrl + F5`。

```html
<!-- .astro / HTML 里：HTML 实体 -->
```

```ts

```

**注意**：

## 1.6 域名与子路径（`astro.config.mjs`）

`astro.config.mjs` 读取两个**构建期环境变量**：

```js
const site = process.env.SITE_URL?.trim() || '';
const rawBase = process.env.SITE_BASE?.trim() || '';
const normalizedBase = rawBase.replace(/^\/+|\/+$/g, '');
const base = normalizedBase ? `/${normalizedBase}/` : '';
```

| 场景 | `SITE_URL` | `SITE_BASE` | 构建后的站点根 |
|---|---|---|---|
| 根路径部署（nginx / 自定义域名 / Cloudflare Pages） | `https://example.com`（可选） | 不设 | `/` |
| 子路径部署（nginx `/music/`） | `https://example.com`（可选） | `/music/` | `/music/` |
| GitHub Pages 项目页 | `https://<owner>.github.io/<仓库名>/` | `/<仓库名>/` | `/<仓库名>/` |
| GitHub Pages 用户主页 / 自定义域名 | `https://<域名>` | 不设或 `/` | `/` |

**变量规则**：

- 两个都可以不设；**不设 = 根路径部署，构建结果与改造前完全一致**（不会产生 `site` / `base` 键）。
- `SITE_BASE` 会被规范成「以 `/` 开头、以 `/` 结尾」：写 `we_sing_laugh_and_live`、`/we_sing_laugh_and_live`、`/we_sing_laugh_and_live/` 效果相同；写 `/` 等于不设。
- `SITE_URL` 原样写入 Astro 的 `site`，用于绝对 URL / SEO；不会自动加末尾斜杠。
- **只在构建时读取**；改完必须重新 `pnpm build`。写进项目根目录的 `.env` 对这两个变量不生效（`astro.config.mjs` 读的是 `process.env`），要在启动命令的环境变量里设。
- 开启子路径后，`pnpm dev` 也要访问 `http://localhost:4321/<base>/`，不是 `http://localhost:4321/`。

**PowerShell（Windows）**：

```powershell
$env:SITE_URL = "https://example.com"
$env:SITE_BASE = "/music/"
pnpm build
```

**bash / CI**：

```bash
SITE_URL=https://example.com SITE_BASE=/music/ pnpm build
```

**验证**：

1. 打开 `dist/index.html`，搜 `_astro`：根路径部署应是 `/_astro/...`；子路径部署应带 `/<base>/_astro/...`，favicon、字体 `url()` 也一样。
2. 本地把 `dist/` 放到对应子目录下起静态服务，访问 `/<base>/`、`/<base>/request/`、`/<base>/about/` 和字体/图标，均应 200。
3. 根路径不应再能访问（子路径构建下，访问 `/` 返回 404 是正常的）。

> 子路径部署时，`public/_redirects` 里的来源路径也要跟着加前缀（该文件只对 Cloudflare 生效；nginx 不用它）。nginx 的具体做法见 3.2。

## 2.1 内容模型速查

### 表

| 表 | 存什么 | 关键字段 |
|---|---|---|
| `groups` | 页面上的分组卡片 | `section`（`voice` 首页 / `song` 歌单）、`group_name`（唯一 id，供 CLI/SQL 使用）、`title`（显示标题）、`sort_order`（越小越靠前）、`is_secret`（1 = 彩蛋分组） |
| `stacks` | 合集（堆叠按钮） | `group_id`、`title`（合集名，空则显示「合集」）、`sort_order`、`is_example` |
| `items` | 每条音频 / 每个按钮 | `group_id`、`stack_id`（空 = 独立按钮）、`kind`（`normal` / `hidden`）、`path`、`zh`、`artist`、`info_*`、`special_effect`、`sort_order`、`is_example` |
| `settings` | 两条空状态文案 | `voice_empty_hint`、`song_empty_hint` |

只读视图 `v_items` 把分组、类型、合集名、条目字段拼在一起，方便在图形工具里浏览。

### `items` 字段 ↔ CLI 参数

| 数据库列 | 生成的 JSON 字段 | `content:add` 参数 | 说明 |
|---|---|---|---|

| `stack_id` | — | `--stack` | 归入合集；合集不存在会自动创建 |
| `info_time` | `info.time` | `--time` | 悬停卡片：时间 |
| `info_title` | `info.title` | `--title` | 悬停卡片：标题 |
| `info_note` | `info.note` | `--note` | 悬停卡片：备注 |
| `info_thumb` | `info.thumb` | `--thumb` | 缩略图：`/thumbs/x.png`（相对 `public/`）或完整图片直链 |

| `created_at` | — | — | 自动写入，不用管 |

> 三个最常说的「信息小卡字段」是 `info_time` / `info_title` / `info_note`，对应 `--time` / `--title` / `--note`；`info_thumb`、`info_duration`、`info_uploader`、`info_songcut_text` 是后来补的可选项，旧库缺列时先 `pnpm content:upgrade`。

### 规则

- **同一分组内 `path` 不允许重复**（`UNIQUE(group_id, path)`）；不同分组可以用同一个文件。本地路径判重忽略大小写；完整远程地址按原样比较。
- `--group` 可以填 `group_name`，也可以填标题；**标题不唯一时只能用 group_name**。
- 歌单分组必须加 `--section song`，否则默认按首页 `voice` 查找分组，会报「分组不存在」。
- 完整远程音频/图片地址直接写在 `path` / `info_thumb`，或按 [OSS 与图床](OSS与图床.md) 用 `PUBLIC_AUDIO_BASE_URL` / `PUBLIC_IMAGE_BASE_URL` 批量换源（这两个是构建配置，改完要重新构建）。
- `info_duration` 只接受非负秒数；`0` 是有效值，显示 `0:00`。
- `--songcut-text` 只在 `--section song` 下接受；文本里的网址、HTML 都按普通文字显示。

**第 1 步：放音频文件**

把文件放到 `public/audio/<分组目录>/`。当前首页可用的音频目录：`public/audio/noise/`、`public/audio/Optimism_lyrics/`、`public/audio/misc_lyrics/`、`public/audio/cats_lyrics/`（这些目录都已存在，里面目前只有 `.gitkeep`）。没有对应目录就自己新建，例如 `public/audio/forgotten/`。

**第 2 步：确认分组 id**

```powershell

```

从输出里选 `noise`、`Optimism_lyrics`、`misc_lyrics`、`cats_lyrics` 之一（这是 `group_name`，`content:add` 用它最稳）。

**第 3 步：加记录（最小命令）**

```powershell
pnpm content:add --group noise --zh "示例音效" --path "noise/示例音效.mp3"
```

**第 4 步：加记录（带悬停卡片等常用字段）**


执行成功后类似输出：

```text
✓ 已添加条目 id=...
    写入前备份：...\data\backups\content-...db
    栏目：渺の怪动静（首页） / 分组：怪叫
    类型：独立按钮
    文字：半夜怪叫
```

几点说明：

- 音频文件**先放**再执行命令最好；CLI 在文件不存在时仍会写入记录，只打印 `⚠ 注意：public/audio/... 目前还不存在`。部署前必须补上文件，否则点击会提示音频不存在。
- `--thumb` 是相对 `public/` 的路径（`/thumbs/...`），不是相对 `public/audio/`。图片要自己放进 `public/thumbs/`（目录已有 `placeholder.svg`）；没有图就删掉这个参数，否则悬停卡片没有缩略图。
- 文字里的中文、空格用双引号包住即可；文件名里有空格也照写，浏览器会自动编码。
- 完整远程音频直链示例：`--path "https://bucket.example.com/audio/noise/a.mp3"`；此时 `content:check` 不会去请求远程地址。

**第 5 步：同步 + 检查 + 构建**

```powershell
pnpm content:sync

pnpm build
pnpm content:verify
```

`pnpm dev` 里看：首页「怪叫」分组出现按钮，点击播放，悬停出现小卡。

## 2.3 新增一首歌

当前歌单分组只有 `song_folk`（民谣）、`song_rock`（摇滚）、`song_pop`（流行）；**没有** `song_acg`，也没有 `covers`。旧文档里的这两个示例已经失效，照抄会报「分组不存在」。先用 `pnpm content:groups` 确认。

**第 1 步：放音频**

歌曲统一放 `public/audio/songs/`（目录已存在），路径写成 `songs/歌名.mp3`。

**第 2 步：加记录**

```powershell
pnpm content:add --section song --group song_folk --zh "歌名" --path "songs/歌名.mp3" --artist "原唱作者" --songcut-text "完整歌切见合集第二集" --time "2024年5月1日" --title "原曲：《示例》" --thumb "/thumbs/封面.png"
```

**要点**：

- **必须写 `--section song`**；漏了会按首页分组找 `song_folk`，直接报分组不存在。
- `--artist` 建议必填：歌单右上角切到「原唱作者」时，没有 `artist` 的歌会全部挤进「未知作者」。
- `--songcut-text` 只是**纯文本**，不能点、不能放网址跳转；只在歌单页的小卡里显示「歌切指路」一行。
- `--title` 是悬停小卡的标题（常用来写原曲名/出处），和按钮文字 `--zh` 不是一回事。
- 歌单也支持 `--stack` 做合集，交互与首页一致（见 2.4）。

**验证**：打开 `/request/`，分别切「歌曲类型」和「原唱作者」；悬停按钮，确认「歌切指路」「原唱」等行出现。

## 2.4 合集（`--stack`）

合集 = 页面上**一个按钮**，里面装多条音频：单击随机播一条，双击随机换当前项（不播放），悬停显示当前项小卡 + 「第 x/x 个」。

```powershell
pnpm content:add --group noise --stack "怪叫合集" --zh "怪叫 · 第一声" --path "noise/怪叫_1.mp3" --title "片段一"
pnpm content:add --group noise --stack "怪叫合集" --zh "怪叫 · 第二声" --path "noise/怪叫_2.mp3" --title "片段二"
```

- 两条命令的 `--stack` 名字完全一致，才会进同一个合集；第一次会自动创建合集。
- 合集名在**同一个分组内**匹配；不同分组可以有同名合集，互不影响。
- 合集按钮显示 `stacks.title` 和成员数量；成员自己的 `--zh` 用于随机到它时的小卡/播放名。
- 空合集：把成员全删掉后，`stacks` 行还在，页面显示数量 0 且按钮禁用；想彻底清掉见下面的 SQL。
- **不要**把 `--hidden` 和 `--stack` 混用：隐藏条目不参与合集的堆叠逻辑，会变成组里的隐藏按钮，语义混乱。

**没有** `content:add-stack` 这类命令；合集只能通过 `content:add --stack` 自动创建。改名/解散用 Studio 或 SQL：

```sql
-- 改名
UPDATE stacks SET title = '新合集名'
WHERE group_id = (SELECT id FROM groups WHERE section = 'voice' AND group_name = 'noise')
  AND title = '怪叫合集';

-- 解散：先让成员变回独立按钮，再删合集（顺序不能反，删合集会级联删成员）
UPDATE items SET stack_id = NULL
WHERE stack_id = (SELECT id FROM stacks
                  WHERE group_id = (SELECT id FROM groups WHERE section = 'voice' AND group_name = 'noise')
                    AND title = '怪叫合集');
DELETE FROM stacks
WHERE group_id = (SELECT id FROM groups WHERE section = 'voice' AND group_name = 'noise')
  AND title = '怪叫合集';
```

改完 `pnpm content:sync`（或 `pnpm build`）。

## 2.5 彩蛋（`--hidden`）

「往日?」彩蛋分两层：

1. 普通分组里的隐藏音频：给某条条目加 `--hidden`，它平时不显示，打开「往日?」后出现在原分组里。
2. 彩蛋分组 `forgotten`（`is_secret=1`）：只有打开「往日?」后才在首页底部出现。

**加一条隐藏音频**：

```powershell
pnpm content:add --group forgotten --hidden --zh "很久以前的声音" --path "noise/往日_旧.mp3"
```

或加在普通分组里：

```powershell
pnpm content:add --group noise --hidden --zh "怪叫彩蛋" --path "noise/彩蛋.mp3"
```

`forgotten` 分组已存在，但 `public/audio/forgotten/` 目录默认没有；你可以自己建，也可以像上面一样把文件放 `noise/`，`path` 按实际写。上面命令里的音频文件要先放进 `public/audio/`，否则添加时会出现「文件不存在」的警告。

**解锁/使用步骤**：

1. 打开首页 `/`。
2. 连续点击**右上角的主题切换按钮 15 次**（每点一次菜单会开/关，属于正常现象）。
3. 中途如果从菜单里选了「日间 / 夜间 / 随系统」，计数会清零，要重新点 15 次。
4. 解锁只写入 `sessionStorage`（键 `lmy-easter-unlock`）；打开「关于」页，会出现「往日?」开关。
5. 打开开关（键 `lmy-past`），回到首页：各分组里的隐藏音频出现，底部出现 `forgotten`「往日」分组。
6. **刷新页面即全部复位**（解锁、开关、隐藏内容一起消失），需要重新解锁。正常跨页跳转不会复位。

**行为**：

- 隐藏音频不参与随机播放，也不能通过分享 URL 直链触发。
- 歌单页不启用彩蛋（`SongBoard.tsx` 里 `enableSecret={false}`）；想在歌单页启用，改成 `enableSecret` 或删掉这一行。
- 每个栏目**只保留一个** `is_secret=1` 的分组；如果建了多个，同步逻辑只会把最后一个当作彩蛋分组。

**验证**：按上面步骤走一遍；再刷新首页，确认隐藏内容消失；F12 → Application → Session Storage 可看到两个键。

## 2.6 特效图标（`--special-effect`）

给按钮文字左侧加「SpecialEffectSize」图标（Segoe Fluent Icons `U+F4A5`）：

```powershell
pnpm content:add --group noise --zh "带特效的音效" --path "noise/特效示例.mp3" --special-effect
```

- `--special-effect` 是**不带值**的开关；写成 `--special-effect true` 会报错。
- 成功后输出会多一行：`特效图标：已开启（按钮文字左侧显示 SpecialEffectSize）`。
- 图标颜色由 `global.css` 的 `.sound-btn__effect` 控制（浅色 `--accent-600`、深色 `--accent-300`、播放态 `currentColor`）。

**只想先看效果、暂时没有音频时**：

- 可以照常添加，CLI 会打印 `⚠ 注意：public/audio/... 目前还不存在`，但记录和图标都会正常显示；点击按钮会提示音频不存在。
- 这只能用于本地看样式；**上线前必须补音频**，不要把不存在的路径留在正式站。
- 如果只是验证图标，放一条很短的静音/测试音频最稳，验证完再换正式文件。

**旧库报错**：

```text
✗ 数据库缺少 special_effect 字段，请先执行 pnpm content:upgrade。
```

执行：

```powershell
pnpm content:upgrade
pnpm content:sync
```

`content:upgrade` 会先在线备份到 `data/backups/`，再补列，可重复执行。

**改图标码位**：改 `SoundBoard.tsx` 第 26 行的 `0xf4a5`；新码位必须在字体里存在，改完硬刷新验证。

## 2.7 分组（SQL 或 Studio）

**目前没有分组管理命令**（没有 `content:add-group` / `content:group`）。加、改、删、排序有三种办法：

1. **WeSingStudio 桌面工具的「分组」页**（相邻仓库 `D:\Webs\we_sing_laugh_and_live-backend`，如果已安装）：列表里选分组，右侧改 `栏目 / group_name / 标题 / 排序 / 是否彩蛋`，可「新建分组」「上移 / 下移」「删除」；删除有二次确认。保存后回到本站执行 `pnpm content:sync`。
2. **DB Browser for SQLite**：打开 `data/content.db` → 「执行 SQL」，粘贴下面的语句 → 执行 → 写回/保存。
3. **`sqlite3` 命令行**（如已安装）：`sqlite3 data/content.db`，再输入 SQL。

> 三种方式都直接改数据库；改完都要同步/重建。

### 新增分组

```sql
-- 首页新增一个普通分组；sort_order 越小越靠前
INSERT INTO groups (section, group_name, title, sort_order, is_secret)
VALUES ('voice', 'new_lyrics', '新分组', 5, 0);
```

- `section` 只能是 `voice` 或 `song`。
- `group_name` 在同一栏目内唯一（`UNIQUE(section, group_name)`），建议用英文/下划线，不要用空格。
- `is_secret` 只有彩蛋分组才填 `1`；普通分组填 `0`。
- 插入后就能用新分组加内容，例如：`pnpm content:add --group new_lyrics --zh "新音效" --path "noise/新音效.mp3"`。验证：`pnpm content:groups` 能看到新分组。

### 改名

```sql
-- 只改显示标题：安全，不影响已有条目
UPDATE groups SET title = '新的显示标题'
WHERE section = 'voice' AND group_name = 'noise';

-- 改 group_name：会改锚点/搜索用的 id；外部收藏链接也会失效，慎用
UPDATE groups SET group_name = 'noise_new'
WHERE section = 'voice' AND group_name = 'noise';
```

`title` 不要求唯一，但**标题重复后 `content:add --group 标题` 会无法判断**，只能填 `group_name`。

### 调整顺序

```sql
BEGIN;

UPDATE groups SET sort_order = CASE group_name
  WHEN 'Optimism_lyrics' THEN 1
  WHEN 'misc_lyrics'     THEN 2
  WHEN 'noise'           THEN 3
  WHEN 'cats_lyrics'     THEN 4
  ELSE sort_order
END
WHERE section = 'voice' AND is_secret = 0;

COMMIT;
```

- 数字越小越靠前；相同数字按 `id` 排。
- 彩蛋分组 `forgotten` 不需要参与普通排序：它由前端固定追加到首页底部。
- 改完 `pnpm content:sync`，刷新看分组顺序。

### 删除分组（⚠️ 级联删除）

**删分组会级联删掉它下面的所有合集和所有条目**（`items.group_id` / `stacks.group_id` 都是 `ON DELETE CASCADE`）。删之前先备份，并先数清楚里面有什么：

```sql
SELECT g.id, g.title,
       (SELECT COUNT(*) FROM items  WHERE group_id = g.id) AS item_count,
       (SELECT COUNT(*) FROM stacks WHERE group_id = g.id) AS stack_count
FROM groups g
WHERE g.section = 'voice' AND g.group_name = 'new_lyrics';
```

确认 `item_count` / `stack_count` 都是 0（或你确实要一起删）再执行：

```sql
PRAGMA foreign_keys = ON;
DELETE FROM groups WHERE section = 'voice' AND group_name = 'new_lyrics';
```

- **必须启用外键**：`PRAGMA foreign_keys = ON;` 要和 DELETE 在同一个连接里执行。DB Browser 可在「工具/编辑」里勾选启用外键，或在「执行 SQL」里先跑这一行；否则删分组不会级联，会留下指向不存在分组的孤儿条目（页面不显示，但数据还在）。
- 删除分组**不会删音频文件**；`public/audio/` 里的文件要自己判断是否删除。`pnpm content:check` 会把「目录里有、库里没有」的文件列出来。
- WeSingStudio 的删除按钮也会二次确认并写明级联范围；用它更不容易手滑。
- 删完：`pnpm content:groups`（确认没了）、`pnpm content:sync`、`pnpm build`。

> 旧文档里的 `cry_lyrics`、`song_acg`、`covers` 示例在当前库中不存在；新增/改名后一律以 `pnpm content:groups` 的输出为准。

## 2.8 修改与删除条目

**先备份**。仓库里的命令（`content:add`、`content:upgrade`、`content:rm-examples -- --yes`）会自动在线备份到 `data/backups/`；**手写 SQL 不会**。手改前先做一份：

```powershell
# 先关闭 Studio、DB Browser、pnpm dev 等可能占用数据库的程序
Copy-Item data\content.db "data\backups\content-before-edit-$(Get-Date -Format 'yyyyMMdd-HHmmss').db"
```

也可以额外导出一份可读 SQL 快照：

```powershell
pnpm content:dump before-edit-2026-10-25.sql
```

快照写到 `data/before-edit-2026-10-25.sql`（只允许 `data/` 内的 `.sql`，不能覆盖 `schema.sql`）。

**找条目 id**：

```powershell
pnpm content:list
```

**改按钮文字**：

```sql
UPDATE items SET zh = '新的按钮文字' WHERE id = 12;
```

**改悬停小卡字段**：

```sql
UPDATE items
SET info_time = '2024年3月15日 21:30',
    info_title = '新的标题',
    info_note = '新的备注'
WHERE id = 12;
```

**改音频路径**：

```sql
UPDATE items SET path = 'noise/新文件.mp3' WHERE id = 12;
```

- 新文件要真的放在 `public/audio/noise/`；同一分组内不能和已有 `path` 重复（忽略大小写）。
- 旧文件如果不再用，可删 `public/audio/noise/旧文件.mp3`，再 `pnpm content:check` 确认没有遗留。

**改归属分组**：

```sql
UPDATE items
SET group_id = (SELECT id FROM groups WHERE section = 'voice' AND group_name = 'noise')
WHERE id = 12;
```

- 目标分组内不能已有同 `path` 的条目。
- 如果这条原本在合集里（`stack_id` 指向旧分组的合集），要同时处理 `stack_id`（设为 `NULL`，或改到目标分组的合集），否则合集关系会错。

**普通 ↔ 彩蛋**：

```sql
-- 改成隐藏音频
UPDATE items SET kind = 'hidden' WHERE id = 12;

-- 改回普通
UPDATE items SET kind = 'normal' WHERE id = 12;
```

改成隐藏时建议把 `stack_id` 设为 `NULL`（隐藏条目不参与合集堆叠）。

**删除条目**：

```sql
-- 最稳：按 id
DELETE FROM items WHERE id = 12;

-- 按路径 + 分组（path 只在同一分组内唯一，必须带分组条件）
DELETE FROM items
WHERE path = 'noise/xxx.mp3'
  AND group_id = (SELECT id FROM groups WHERE section = 'voice' AND group_name = 'noise');
```

删除后：`pnpm content:sync` → `pnpm content:check` → `pnpm build` → `pnpm content:verify`。

> 目前**没有** `content:edit` / `content:rm` 命令；不要照着旧文档或别的项目猜参数。图形化编辑可用 WeSingStudio 的条目页（如果版本支持）；用 SQL 时优先按 `id`，不要按 `path` 单独删。

## 2.9 同步与校验

| 命令 | 做什么 | 什么时候跑 | 不跑会怎样 |
|---|---|---|---|
| `pnpm content:sync` | 读 `data/content.db`，重写 `src/data/content.json` 和 `data/content-dump.sql`（内容没变则不写） | 手改数据库 / SQL / Studio 保存后 | 页面还是旧内容；`content:verify` 可能和库对不上 |
| `pnpm content:check` | 双向核对：库里的本地文件在不在、`public/audio/` 里有没有未入库文件；完整远程地址跳过 | 加/删音频文件、删条目后 | 不知道有没有漏文件/孤儿文件 |
| `pnpm content:verify` | 核对构建产物：首屏 HTML + JS bundle 是否含库里的条目与字段；**需先 `pnpm build`** | 每次 `pnpm build` 后 | 内容写了但没进产物，可能上线才发现 |
| `pnpm build` | 先自动 `content:sync`，再 `astro build` 生成 `dist/` | 每次部署前 | 没有可部署的产物 |
| `pnpm test` | 跑 81 个自动测试（只写临时数据库） | 改代码后；发布前 | 回归问题可能漏掉 |
| `pnpm content:stats` | 每个分组的条目统计 | 巡检、确认加没加进去 | — |
| `pnpm content:groups` | 列出分组 id / 标题 / 彩蛋标记 | 加内容/分组前 | 容易把 `group_name` 写错 |
| `pnpm content:list` | 列出所有条目（id、分组、类型、路径、特效） | 找 id、核对 | — |
| `pnpm content:dump [文件名]` | 导出 `data/` 内的 `.sql` 快照 | 手改前留档 | — |

**推荐顺序**（内容改动）：

```powershell
pnpm content:sync
pnpm content:check
pnpm build
pnpm content:verify
```

- 只加内容时直接 `pnpm build` 也会自动同步；但先跑 `content:sync` 能在 git diff 里先看清 `content.json` / `content-dump.sql` 的变化，出问题更容易定位。
- `pnpm dev` 只在**启动时**同步一次；运行期间改了数据库，需要另开终端跑 `pnpm content:sync`（Vite 会感知 JSON 变化）或重启 `pnpm dev`。
- 空库时 `content:verify` 会显示 `条目校验：0 条 / 字段校验：0 个` 并通过——这只说明产物与空库一致，**不能证明有内容时的播放/交互**；有内容后要再跑一次，并实际点按钮。
- `content:check` 在配置了 `PUBLIC_AUDIO_BASE_URL` 时仍只核对本地目录，远程文件不会请求；提示「本地缺失」不等于 OSS 上没有。

## 2.10 常见错误

| 报错 / 现象 | 原因 | 处理 |
|---|---|---|
| `✗ 分组不存在或标题不唯一，请用 content:groups 中的分组 id。` | `--group` 拼错；歌单分组忘了 `--section song`；分组标题重复 | 跑 `pnpm content:groups`，复制 `group_name` 原样填；歌单加 `--section song` |
| `✗ 音频路径必须相对 public/audio，或填写完整 HTTP(S) 直链；不能带盘符或跳出目录。` | `--path` 写了 `public/audio/...`、`D:\...`、`../`、空路径或非法字符 | 改成 `noise/x.mp3` 这种相对 `public/audio` 的路径，或用完整 `https://` 直链 |
| `✗ 同一分组内已存在相同音频路径（id=...）：...` | 同组重复路径（本地忽略大小写） | 换文件名/换分组；确实要替换就先删旧条目（见 2.8） |
| `⚠ 注意：public/audio/... 目前还不存在，记得把音频文件放进去。` | 先加了记录，文件还没放 | 把文件放到对应路径；或改 `path` |
| `✗ 数据库缺少 special_effect 字段，请先执行 pnpm content:upgrade。` | 旧库没有列 | `pnpm content:upgrade` → `pnpm content:sync` |
| `✗ 数据库缺少对应的信息小卡字段，请先执行 pnpm content:upgrade。` | 旧库缺 `info_duration/info_uploader/info_songcut_text` | 同上 |
| `✗ --special-effect 是不带值的开关参数，直接写 --special-effect 即可。` | 给开关带了值 | 去掉值，只写 `--special-effect` |
| `✗ 歌切指路仅适用于歌单，请使用 --section song。` | 在首页条目上用了 `--songcut-text` | 加 `--section song`，或删掉该参数 |
| `✗ --duration 必须是非负的音频时长（单位秒）。` | 写了 `1:23`、负数、空值 | 改成秒数，如 `83` 或 `12.5` |
| `✗ 未知命令：...。请运行 pnpm content:help。` | 命令名写错 | 以 `pnpm content:help` 为准 |
| 页面内容没变化 | 改了库但没同步；`dev` 运行中改库；浏览器缓存 | `pnpm content:sync`（或重启 dev）；`Ctrl + F5`；确认看的是新 `dist/` |
| 音频 404 / 点击提示不存在 | 文件没放、路径大小写不一致、部署漏传 `audio/` | 对照 `public/audio/` 实际文件名（Linux 区分大小写）；重传 `dist/audio/` |
| `✗ 找不到 dist/，请先执行 pnpm build` | `content:verify` 在构建前跑 | 先 `pnpm build` |
| `✗ 找不到 src/data/content.json，请先执行 pnpm content:sync` | JSON 被删/没生成 | `pnpm content:sync` |
| `✗ 数据库不存在：...` | `data/content.db` 丢了 | 从 `data/backups/` 恢复，或 `pnpm content:migrate` 从 SQL 快照恢复（仅当数据库不存在） |
| 移动项目文件夹后 `ERR_PNPM_ABORTED_REMOVE_MODULES_DIR_NO_TTY` | pnpm 的 `node_modules` 记录了旧绝对路径 | 删 `node_modules` 后 `pnpm install --offline`（仓库在本机有离线包缓存） |
| 图标显示成方块/空白 | 字体 404、MIME 不是 `font/ttf`、码位不在字体里 | 见 3.6 的字体检查；确认 `public/fonts/SegoeFluentIcons.ttf` 已部署 |

它实际执行：

```text
node scripts/content-sync.mjs   # 先同步数据库 → content.json + content-dump.sql

```

所以**构建前不需要手动同步**；构建会自动带上最新内容。

产物 `dist/` 里主要有：

```text
dist/
├─ index.html              # 首页

├─ about/index.html        # 关于
```

## 3.2 nginx（现有方式）

以下按 [nginx 部署指南](../部署/部署指南.md) 与 [部署/nginx.conf](../部署/nginx.conf) 给出最短可行路径。以下命令里的 `服务器IP` 换成实际地址；端口示例用 `80`，如果你沿用仓库配置的 `25565`，把两处 `listen` 和放行端口一起改。

**① 本地构建 + 打包**

```powershell
pnpm build
tar -czf site.tar.gz -C dist .
```

**② 上传并解压到站点目录**

```powershell
scp site.tar.gz root@服务器IP:~/
ssh root@服务器IP "mkdir -p /var/www/we-sing-laugh-and-live && tar -xzf ~/site.tar.gz -C /var/www/we-sing-laugh-and-live && rm -f ~/site.tar.gz && echo OK"
```

确认解压结果（应直接看到 `index.html`，不要多套一层目录）：

```powershell
ssh root@服务器IP "ls /var/www/we-sing-laugh-and-live"
```

> 下面的路径统一用新目录名 `/var/www/we-sing-laugh-and-live`。如果服务器上已有旧的 `/var/www/yuki-voice-button`，也可以整体沿用旧目录：把命令里的新路径全部换回旧路径，并把第 ④ 步 `sed` 里的路径替换去掉（其余不变）。

**③ 安装 nginx（如未安装）**

```bash
apt update
apt install -y nginx
systemctl is-active nginx
```

**④ 写入站点配置**

可以直接上传仓库里的 `部署/nginx.conf`，然后改两行：`listen 25565` → 你的端口、`root /var/www/yuki-voice-button` → 你的站点目录。

```powershell
scp 部署/nginx.conf root@服务器IP:~/
ssh root@服务器IP "sed -i 's#/var/www/yuki-voice-button#/var/www/we-sing-laugh-and-live#; s/25565/80/g' ~/nginx.conf && cp ~/nginx.conf /etc/nginx/sites-available/we-sing && ln -sf /etc/nginx/sites-available/we-sing /etc/nginx/sites-enabled/we-sing && nginx -t && systemctl reload nginx"
```

> 上面的 `sed` 只在按默认路径/默认端口部署时省事；改完请 `ssh root@服务器IP "grep -n 'listen\|root' /etc/nginx/sites-available/we-sing"` 核对一遍。CentOS / RHEL / Rocky 把配置放 `/etc/nginx/conf.d/we-sing.conf`，不用软链。

> ⚠️ **用 80 端口时**，Ubuntu 装完 nginx 自带 `/etc/nginx/sites-enabled/default`，它会抢走 `IP:80` 的默认响应，浏览器会看到「Welcome to nginx」而不是本站。上线前移除它：
>
> ```bash
> ssh root@服务器IP "rm -f /etc/nginx/sites-enabled/default && nginx -t && systemctl reload nginx"
> ```
>
> 不用 80（例如沿用 `25565`）可以跳过这一步。

如果要自己写一份最小配置，核心是：

```nginx
server {
    listen 80;
    server_name _;
    root /var/www/we-sing-laugh-and-live;
    index index.html;
    charset utf-8;

    location / { try_files $uri $uri/ =404; }

    location ~* \.html$ {
        add_header Cache-Control "no-cache";
        try_files $uri =404;
    }

    location /_astro/ {
        expires 1y;
        add_header Cache-Control "public, immutable";
        try_files $uri =404;
    }

    location ~* \.(ttf|otf|woff|woff2|eot)$ {
        types { font/ttf ttf; font/otf otf; font/woff woff; font/woff2 woff2; }
        expires 30d;
        add_header Cache-Control "public";
        try_files $uri =404;
    }

    location ~* ^/(icons|thumbs|fonts)/ {
        expires 30d;
        add_header Cache-Control "public";
        try_files $uri =404;
    }

    gzip on;
    gzip_vary on;
    gzip_min_length 1024;
    gzip_types text/css text/plain application/javascript application/json image/svg+xml;

    location ~ /\. { deny all; }
}
```

仓库里的 `部署/nginx.conf` 还多了日志路径等细节，建议优先用它。

**⑤ 放行端口**

```bash
ufw allow 80/tcp
ufw reload
```

云服务器还必须在控制台**安全组**添加入方向 TCP 80（或你的端口）；漏了会出现「服务器本机 curl 正常、外面打不开」。

**⑥ 验证**

```bash
curl -sI http://服务器IP/ | head -3
curl -s http://服务器IP/ | grep -o '<title>[^<]*</title>'
curl -sI http://服务器IP/fonts/SegoeFluentIcons.ttf | grep -i content-type   # 期望 font/ttf
```

浏览器打开 `/`、`/request/`、`/about/`，点音频，拖进度条。

**以后更新内容**：重新 `pnpm build` → 重打包上传 → 覆盖站点目录；只换静态文件**不需要重启 nginx**。只有改了 `/etc/nginx/` 下的配置才需要 `nginx -t && systemctl reload nginx`。

**子路径场景（挂在 `http://服务器IP/music/`）**：

1. 构建时设 `SITE_BASE=/music/`（见 1.6）。
2. 把 `dist/` 内容放到 `/var/www/we-sing-laugh-and-live/music/`（`music/index.html` 直接存在）。
3. nginx 的 `root` 指到父目录：

```nginx
root /var/www/we-sing-laugh-and-live;
location / { try_files $uri $uri/ =404; }
```

4. 访问 `http://服务器IP/music/`、`/music/request/`、`/music/about/`。

- 不要用 `alias` 硬顶，页面里的资源路径已经带 `/music/` 前缀，`root` 指父目录最稳。
- 子路径下 `location /_astro/`、`^/(icons|thumbs|fonts)/` 这些规则不会匹配带前缀的请求；默认 `location /` 仍能正确返回文件，只是少了长缓存。需要长缓存就再加 `/music/_astro/` 等带前缀的 location。

## 3.3 Cloudflare Pages

仓库已备好 `wrangler.jsonc`（`pages_build_output_dir: "./dist"`）、`public/_headers`、`public/_redirects`、`.node-version`。详见 [Cloudflare Pages / GitHub Pages](部署-Cloudflare-GitHubPages.md)。

### 方式 A：GitHub 集成（推荐，零凭据）

Cloudflare 面板 → **Workers & Pages** → **Create** → **Pages** → **Connect to Git**，授权并选仓库，然后按下表填：

| 字段 | 值 |
|---|---|
| Production branch | `main` |
| Framework preset | `Astro` 或 `None`（只是预填命令） |
| Build command | `pnpm build`（**不要**再写 `pnpm install`，Pages 会自动装依赖） |
| Build output directory | `dist` |
| Root directory | 留空（仓库根） |

**环境变量**（Production 与 Preview 都加）：

| 变量 | 值 | 说明 |
|---|---|---|
| `NODE_VERSION` | `24.19.0` | 与 `.node-version`、本机一致；v3 镜像默认是 22.x |
| `PNPM_VERSION` | `11.21.0` | v3 镜像默认 pnpm 10.x，且不会从 lockfile 推断版本 |
| `SITE_URL` | `https://<项目名>.pages.dev` | 写入 Astro `site`，用于 SEO/绝对 URL |
| `SITE_BASE` | **不设**（或 `/`） | Pages 走域名根；设了子路径会导致资源 404 |
| `CONTENT_SOURCE` | 不设（= local） | 只有切 D1 构建期取数才设 `d1` |

首次部署后，`wrangler.jsonc` 里的 `name` 必须与 Pages 项目名一致（当前 `we-sing-laugh-and-live`，只允许小写字母/数字/连字符）；不一致就改项目名或改 `wrangler.jsonc`。提交该文件后，面板里的对应字段会变成只读。

## 3.4 GitHub Pages

### 一次性设置

1. 仓库 Settings → **Pages** → Build and deployment → Source 选 **GitHub Actions**（不要选 Deploy from a branch）。
2. 打开 Actions 页，选中「部署到 GitHub Pages」，点 **Run workflow**。

当前 `.github/workflows/deploy.yml` 的触发方式是**仅手动**：

```yaml
on:
  # ⚠️ 当前仅手动触发...
  #   push:
  #     branches: [main]
  workflow_dispatch:
```

workflow 内部已经自动设置项目页子路径，不需要你在 Actions 里再加变量：

```yaml
env:
  SITE_BASE: /${{ github.event.repository.name }}/
  SITE_URL: ${{ format('https://{0}.github.io/{1}', github.repository.owner, github.event.repository.name) }}
```

也就是说项目页地址是 `https://<owner>.github.io/<仓库名>/`，构建产物里的资源会自动带 `/<仓库名>/` 前缀。

### 想改成「推 main 自动部署」

编辑 `.github/workflows/deploy.yml`，把 `on:` 下面两行注释去掉：

```yaml
on:
  push:
    branches: [main]
  workflow_dispatch:
```

然后提交这个 workflow 改动并推到 `main`；之后每次推 `main` 都会构建并发布。`permissions`、`concurrency` 不用动。

### 本地手动构建 GitHub Pages 产物（验证用）

```powershell
$env:SITE_BASE = "/we_sing_laugh_and_live/"
$env:SITE_URL = "https://<owner>.github.io/we_sing_laugh_and_live/"
pnpm build
```

检查 `dist/index.html` 里的 `_astro`、`favicon`、字体路径是否都带 `/we_sing_laugh_and_live/`。

### 自定义域名

1. Pages Settings → Custom domain 填域名，按提示配 DNS（CNAME 到 `<owner>.github.io`）。
2. **同时**把 workflow 里的 `SITE_BASE` 改成 `/`、`SITE_URL` 改成 `https://你的域名/`，重新构建；否则资源仍带旧子路径。
3. 自定义域名后仓库根目录的 `CNAME` 文件不会自动改设置，用 Settings 或 API 配。

### 注意

- 走 Actions artifact 发布**不需要** `.nojekyll`；只有把 `dist` 推到分支发布时才需要（Jekyll 会吞 `_astro/`）。
- GitHub Pages 不读 `_headers`，字体 MIME / 缓存都不可控；如果字体被当成 `application/octet-stream`，先确认 `SITE_BASE` 生效，再考虑把字体走 Astro 资源管线。
- 免费计划要求仓库公开；私有仓库发 Pages 需要付费计划。

## 3.5 可选：D1 构建期数据源

默认仍读本地 `data/content.db`，什么都不用改；只有想让构建时从 Cloudflare D1 取内容，才设置 `CONTENT_SOURCE=d1` 并配 D1 REST 凭据：

## 3.7 回滚

先判断坏在哪一层，**按「数据库 → 生成物 → 构建 → 部署」的顺序回滚**；不要只换其中一个。

| 坏的是… | 用什么回滚 |
|---|---|
| 内容（条目/分组/文案） | `data/backups/` 里的数据库备份，或 `git restore data/content.db` |
| 代码（页面/样式/配置） | `git restore <文件>`（未提交）或 `git revert <提交>`（已提交） |
| 线上产物 | 重新上传上一版 `site.tar.gz` / `dist`；Cloudflare Pages 面板回滚到上一个部署；GitHub Pages 重跑上一个成功的 workflow |

### 内容回滚（推荐顺序）

**① 先停止写入**：关闭 WeSingStudio、DB Browser、`pnpm dev` 等可能占用 `data/content.db` 的程序。

**② 找到备份**：

```powershell
Get-ChildItem data\backups | Sort-Object LastWriteTime -Descending | Select-Object -First 10 Name, LastWriteTime
```

备份名形如 `content-2026-10-25T...-<uuid>.db`，是完整数据库文件；`data/backups/` 已被 `.gitignore` 忽略，**只存在本机，git 里没有**。

**③ 如果当前库也可能有用，先另存一份**：

```powershell
Copy-Item data\content.db "data\backups\content-before-rollback-$(Get-Date -Format 'yyyyMMdd-HHmmss').db"
```

**④ 用备份覆盖当前库**（确认没有程序占用后）：

```powershell
# 下面取「最新」的一份备份；如果要恢复的不是最新那份，把 $backup 换成对应文件的完整路径
$backup = Get-ChildItem data\backups\content-*.db | Sort-Object LastWriteTime -Descending | Select-Object -First 1
$backup.FullName
Remove-Item data\content.db-wal, data\content.db-shm -ErrorAction SilentlyContinue
Copy-Item $backup.FullName data\content.db -Force
pnpm content:sync
```

**⑤ 重建 + 校验 + 部署**：

```powershell
pnpm build
pnpm content:verify
```

然后把新的 `dist/` 重新部署。

> `pnpm content:migrate` **只用于数据库不存在时**从 `data/content-dump.sql` 恢复，不会覆盖现有库，也不能当回滚命令用。

### 代码回滚

未提交的改动：

```powershell
git status --short
git restore src/data/site.ts src/styles/global.css
```

已提交但有问题：

```powershell
git revert <坏提交的 hash>
pnpm build
```

- 不要用 `git checkout` 去恢复 `dist/`：它本来就不入库，恢复不了。
- 回滚代码后仍要 `pnpm build` 重新生成 `dist/`，不能拿旧 `dist/` 配新代码。
- 恢复数据库后一定要重新 `pnpm content:sync`，**不要**单独恢复 `src/data/content.json` 或 `data/content-dump.sql`——它们必须从当前数据库重新生成。

### 线上产物回滚

- **nginx**：保留上一版 `site.tar.gz`，重传并解压覆盖即可；只换静态文件不需要 `systemctl reload nginx`。
- **Cloudflare Pages**：面板 → 项目 → Deployments → 选上一个正常部署 → **Rollback**；或 `git revert` 后重跑构建。
- **GitHub Pages**：Actions 里重跑上一个成功部署；或 revert 后重新触发 workflow。
